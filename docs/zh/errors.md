# 错误码与错误信息

SDK 的错误统一落在 `JiYanSDK_Result::Data`：`ok` 表示业务是否成功，`code` 是数值码，`message` 是可直接展示的文案，`raw` 保存解密后的响应原文。`JiYan_Last_Request_Ok` 是线程局部标志，异步请求结束时以它为准。错误文案主要来自协议层、HTTP 层和业务封装，`SDK_Result.cpp` 本身不产生错误字符串。

## 错误码

| code | 含义 | 产生位置 | 处理建议 |
| --- | --- | --- | --- |
| 0 | 成功 | 协议层 `success=true` | 读取 `Data` 中的业务字段 |
| -1 | 没有拿到响应 | `Response` 默认值；传输失败 | 检查网络、DNS、端口、`api_url`、HTTP 状态 |
| 1002 | 响应解密失败 | `Decode` 解密为空 | 核对 `Crypto_Method` 与 `Crypto_Key` |
| 1003 | 响应校验失败 | 验签、`rc` 或云控身份绑定 | 核对签名配置、请求是否被代理/缓存、身份是否变化 |
| 9999 | 客户端异常、`JiYan_Error`、或服务端未给业务码 | 异常捕获、错误前缀、失败但 `code=0` | 先读 `message`，再按文案分类 |
| 其他 | 服务端业务码 | 响应 JSON 的 `code` | 按业务含义处理，不要当作传输错误 |

`ok=false` 且 `code=-1` 时通常连 HTTP 状态都没有；`code=9999` 时 `message` 往往就是异常原文。服务端返回业务失败但 `code` 为 0 时，SDK 会强制改为 9999。

## JiYan_Error 前缀

如果响应体是纯文本且以 `JiYan_Error` 开头，SDK 跳过解密，取第 11 个字符之后的内容作为 `message`，并把 `code` 置为 9999。这个前缀只会在读取方向出现，客户端自身从不生成。它通常来自网关、WAF、PHP 致命错误或维护页，说明请求没有进入正常协议处理。排查时看服务端与反代日志，不要只盯加密配置。

## 本地配置错误

这些错误在发请求之前抛出，最终表现为 `code=9999`：

| message | 原因 |
| --- | --- |
| `加密或签名方式编号非法` | `Crypto_Method` 不在 0–8 或 `Signature_Method` 不在 0–14 |
| `Signature_Key 未配置` | 签名方式非 0 但密钥为空 |
| `Crypto_Key 未配置` | 加密方式为 1、4、5、6、7、8 但密钥为空 |
| `本地签名失败` | 签名实现返回空，通常是密钥或参数编码异常 |
| `本地加密失败，请检查 Crypto_Key 与 Crypto_Method` | 加密结果为空，常见于方式 1 的密钥/IV 无效 |
| `请求参数必须是字符串或整数，数组应先编码成JSON字符串` | 传入了数组或对象参数 |
| `此客户端只允许卡密、同行识别和云更新接口` | `set_php` 指向了未开放的接口文件 |
| `新 HTTP 客户端包不开放管理操作，请在 HTTPS 主站后台操作` | 调用了管理类接口，如 `GetFileList` |

## 协议与响应错误

| message | 原因 | 建议 |
| --- | --- | --- |
| `响应解密失败（Crypto_Key / Crypto_Method 配置不匹配）` | 密文无法解开 | 两端算法、密钥口径、IV 复用方式必须一致 |
| `响应签名校验失败` | 响应签名与本地复算不一致 | 核对 `Signature_Method`、`Signature_Key` 与 canonical 串 |
| `响应校验失败（rc 不匹配或缺失）` | 响应不属于本次请求 | 禁用缓存/重放代理，确认服务端回显本次 `rc` |
| `云控响应身份绑定不匹配` | 云控响应的 nonce、scope、app、卡密或设备不一致 | 检查请求期间是否切换账号、卡密或设备 |
| `响应结构非法` | JSON 缺少 `success`/`message`/`data` 或类型错误 | 查看服务端是否返回了非协议页面 |
| `响应解析失败：...` | 业务层二次解析失败 | 结合 `raw` 与 `message` 定位 |
| `网络请求失败` | 传输失败且没有更具体信息 | 按下面的 HTTP 错误继续排查 |

## HTTP 错误

HTTP 层失败时 `code=-1`，`message` 形如 `HTTP <状态码> - <中文提示>`。常见状态码：

| 状态 | 提示摘要 | 典型原因 |
| --- | --- | --- |
| 400 | 请求格式错误，检查 JSON/字段 | 请求体被改写、字段缺失 |
| 401 | 未授权，账号/口令/Token 无效或过期 | 账号信息错误 |
| 402 | 需要付费，余额不足或未开通 | 会员能力未开通 |
| 403 | 被拒绝，无权限/IP 限制/WAF | 防火墙或来源限制 |
| 404 | 接口不存在，检查 `api_url` 是否以 `/api/` 结尾 | 地址少了 `/api/` 或接口文件名错误 |
| 405 | 只接受 POST | 用 GET 访问了接口 |
| 408 | 请求超时 | 网络慢或服务端繁忙 |
| 413 | 请求体过大 | 批量参数太多，分批请求 |
| 429 | 触发频率限制 | 降低请求频率 |
| 500 | 服务端内部错误 | 后端异常，查看服务端日志 |
| 502 | 网关错误，PHP-FPM 未启动/重启/超时 | 后端进程不可用 |
| 503 | 服务暂不可用，维护或进程池满 | 稍后重试 |
| 504 | 网关超时 | 后端处理过慢 |

传输层还可能直接给出 `HTTP 网络操作超时`、`HTTP DNS/地址解析失败：...`、`HTTP 连接失败：...`、`HTTP 发送失败：...`、`HTTP 接收失败：...`、`HTTP 响应正文超过 8 MiB`、`HTTP 响应头、分块行或尾部超过 32 KiB 限制` 等文案。HTTPS 地址会被明确拒绝：`纯 Socket HTTP 不支持 HTTPS，禁止降级；请使用 http:// 地址`。

## 业务与云更新错误

卡密、同行识别和公告的业务失败由服务端返回 `code` 与 `message`，SDK 原样透出。云更新在本地还会产生一批校验文案，例如：

| message | 原因 |
| --- | --- |
| `文件名或本地 MD5 无效` | MD5 不是 32 位 hex 或文件名为空 |
| `本地 SO 文件无法读取或未加载，不能进行 MD5 检查` | `/proc/self/maps` 中找不到或无法读取该 SO |
| `下载文件名、摘要或票据不匹配，发布可能已变更，请重新检查版本` | 取链接期间发布被替换 |
| `下载文件 MD5 不匹配，未提交回执` | 落盘文件损坏或被改写 |
| `回执响应未确认下载完成` | 服务端 `confirmed != 1` |
| `已有异步请求正在进行，请稍后重试` | 兼容异步接口并发调用 |

云控绑定失败不会写入 `Data.code`，而是让绑定函数返回 `false` 并把原因放进 `最后错误()`，例如键名非法、重复绑定、地址重复、超过 100 个绑定。

## 排查顺序

1. 先看 `Data.ok`、`Data.code`、`Data.message`，再看 `raw` 是否为空。
2. `code=-1` 查网络与 HTTP；`1002` 查加密；`1003` 查签名、`rc` 与身份；`9999` 读文案。
3. 设备码为空会导致验证与云控异常，先确认 `set_device_id` 在 `init` 前调用且值稳定。
4. 心跳连续失败两次会把库置为锁定状态，`is_locked()` 为真；处理完网络问题后重新验证卡密。
5. 日志中不要打印完整密钥、卡密或账号；需要比对时只打印长度与摘要。
